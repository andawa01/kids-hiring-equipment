# PartyPlay backend

FastAPI + SQLAlchemy 2.0 + PostgreSQL. Implements the catalogue read API, the booking
engine (availability checks, holds, approval) and the first admin endpoints.

## Setup

```bash
docker compose up -d db                 # from the repo root (or use your own Postgres 16)
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env                    # then set JWT_SECRET
alembic upgrade head
python -m app.scripts.seed              # sample equipment, package, offer
python -m app.scripts.create_admin you@example.com
uvicorn app.main:app --reload           # docs at http://localhost:8000/docs
```

## Tests

Create a second database for tests (never point tests at real data, they truncate tables):

```bash
createdb -h localhost -U partyplay partyplay_test    # or via psql
pytest                                                # uses TEST_DATABASE_URL or the default test DB
```

The suite includes real multi-threaded concurrency tests; they need PostgreSQL (row locks).

## How double booking is prevented

See `app/services/availability.py` and `app/services/bookings.py`.

1. Booking dates are inclusive on both ends.
2. Stock is held by `approved` bookings and by `pending` ones whose `expires_at` is in the future.
3. Availability = `total_quantity - peak daily usage` over the requested range.
4. `create_booking` and `approve_booking` run the check inside a transaction that first locks the
   relevant `equipment_inventory` rows (`SELECT ... FOR UPDATE`, sorted by id to avoid deadlocks).
5. `approve_booking` re-checks, excluding the booking's own hold.
6. `python -m app.tasks.expire_holds` tidies lapsed holds; correctness does not depend on it.

## IDs

Every primary key is a random UUID (v4) generated by the backend (`default=uuid.uuid4`).
Bookings also have a short human-friendly `reference` (e.g. `PP-7K3QWD`) for customers.

## Layout

```
app/
  api/        public.py, admin.py, deps.py
  core/       config, db, security, errors
  models/     SQLAlchemy models
  schemas/    Pydantic request/response models
  services/   availability.py, pricing.py, bookings.py
  scripts/    create_admin.py, seed.py
  tasks/      expire_holds.py
alembic/      migrations
tests/
```
